# Mobile layouts and artifacts

Open a thread’s artifact library to read the code and diffs in its assistant messages. Named fences collect revisions by language and filename. Unnamed excerpts remain separate. The library derives its contents from the loaded transcript, with the most recent assistant messages taking priority within the reader’s memory budget. The original conversation remains on the gateway. HTML and SVG open as selectable source. A deliberate copy places the chosen version in the Android clipboard and marks it as sensitive.

In a coding discussion, ask “Turn this review into a tool I can use again.” The thread menu also provides **Create a tool for this thread**. It stages an editable request alongside any existing draft. A named tool in an assistant reply lets you try the form in that discussion. Pin the tool to return to it later. When Hermes proposes a revision, compare what changed before adopting it. Undo restores the previous choice. Each new request identifies the pinned page to Hermes. Field entries stay on the phone until you transfer them to a message and send it.

Ask for a calendar event, text to share or a place to find on a map in the same conversation. Hermes proposes a native action to review and open on your phone. [Android actions and examples](android-actions.md)

For a nearby restaurant guide, ask “Find restaurants near me.” You choose which location to share. [Location and restaurant sources](nearby-restaurants.md)

Ask Hermes to rearrange a built-in screen, replace its authenticated content, or create a named screen for a task. It can build forms, link workspace pages, show the active conversation title, and order the native composer, status, and transcript. On phones, three living bottom tabs (**Chats**, **Notes & tasks**, **Apps**) sit in an IME-aware bar alongside persistent top-bar **Universal search** and **Settings** actions; on tablets (`>= 720 dp`), they shift to a **92 dp** navigation rail alongside the collapsible discussion sidebar. Open the resulting layout proposal from the thread’s artifact library or Live UI bar. The preview names the destination screen and shows the proposed sections. Select **Apply layout…** and confirm to use it for this profile. The native screen-layout menu in **Apps** provides **Undo change** and **Restore**. A change retains its preceding revision for undo. Applying and undoing keep each profile’s layouts in its encrypted account storage. For atomic `ui.patch` operations, WCAG-AA Day/Night theme overrides, Surfaces v2 interactive controls, and profile-scoped Home Screen widgets, see [Live UI Modding & On-the-Fly Widgets](live-ui-and-widgets.md).

If a built-in screen’s saved layout cannot be read, choose **Restore defaults** from **Apps** (or the screen-layout menu), select that screen, and confirm **Restore**. This discards its unreadable layout history for the unlocked profile and allows a new proposal to be applied.

For damaged named pages, open **My screens** and choose **Repair library…**. Read the confirmation before selecting **Repair**. Repair keeps recoverable pages and revisions. If the entire library is unreadable, confirming clears all its named pages and revisions for this profile.

The mobile run includes compact layout instructions. Operators who want the full instructions available to Hermes in other sessions can install the [Hermes Mobile workspace skill](../skills/hermes-mobile-workspace/SKILL.md) in the active profile’s skills directory. Copy the complete `hermes-mobile-workspace` folder there. The skill contains the schema, editing options and working examples. Layout proposals use installed native actions. Changes requiring a new native capability go through the application's source review, build, signing, and update process.

Open **My screens** to reach an installed page. A custom form opens an editable review of the draft it creates. **Move to draft** transfers that text into the native conversation, where **Send** submits it. The native screen-layout menu remains accessible when a custom layout replaces an entire screen. Removing a custom page retains one undo revision. If you choose to erase that removed revision, the library frees the page’s place.
