Documentation Hermes Mobile

Référence technique alignée sur le client Android API 28–36 et le fork serveur LLM-4-People/hermes-agent (révision 0ae4511b).

1. Démarrage rapide & déploiement sur un seul hôte HTTPS

Hermes Mobile est conçu pour servir plusieurs personnes sur une unique adresse HTTPS (par exemple https://hermes.example.com) via des préfixes /p/<profil>. Aucun sous-domaine individuel n’est nécessaire.

Construire l’image serveur épinglée

revision=$(python3 -c 'import runpy; print(runpy.run_path("verification/gateway_fixture.py")["PINNED_REVISION"])')
checkout=$(mktemp -d)
git -C "$checkout" init -q
git -C "$checkout" fetch --depth=1 --no-tags https://github.com/LLM-4-People/hermes-agent.git "$revision"
git -C "$checkout" archive "$revision" | \
  docker build -t "hermes-mobile-gateway:$revision" -
image=$(docker image inspect --format '{{.Id}}' "hermes-mobile-gateway:$revision")

Générer une pile multi-profils avec Caddy TLS

deployment="$HOME/.local/share/hermes-mobile-deployment"
python3 deploy/accounts.py "$deployment" --image "$image" \
  --host hermes.example.com \
  --profile alice --profile bob \
  --push alice
docker compose -f "$deployment/compose.json" config --quiet
docker compose -f "$deployment/compose.json" up -d --build
  • Clés 256 bits distinctes : chaque profil reçoit sa propre clé API dans accounts/<profil>/gateway.env et ses propres identifiants fournisseur dans provider.env.
  • Connexion sur Android : dans Connecter Hermes, saisissez https://hermes.example.com et le nom Profil serveur (ex. alice). L’application compose /p/alice automatiquement.
  • APK signé & mises à jour GitHub intégrées : téléchargez la dernière version APK depuis GitHub Releases. Dans l’application, le vérificateur de mises à jour contrôle les sorties GitHub, vérifie l’empreinte SHA-256 de l’APK téléchargé (fail-closed) et ne lance l’installeur Android qu’après confirmation explicite.
  • Compilation APK locale : JDK 21 + Android SDK 36, puis ./gradlew :app:assembleDebug et adb install -r app/build/outputs/apk/debug/app-debug.apk.

2. Fork serveur compagnon (LLM-4-People/hermes-agent)

Hermes Mobile nécessite le fork LLM-4-People/hermes-agent (révision vérifiée 0ae4511b126efb5cba5bb75a7d354cf1c4406a8d). Les fonctionnalités sont découvertes dynamiquement via GET /v1/capabilities afin que le client échoue de façon sûre si une capacité manque.

Domaine Routes / Événements du fork Comportement client
Multi-profils /p/{profile}/* Clé API par profil fail-closed (HTTP 401), zéro sous-domaine.
Live UI v2 SSE ui.patch, /api/mobile/ui/* Validation locale, aperçu non bloquant, rollback multi-révisions.
Livraisons Push mobile_deliver, /api/mobile/deliveries, mobile_state.db Boîte de réception Activité + réveils opaques sans fuite.
Brain Studio /api/memory, /api/notes, /api/habits, /api/shares, /api/search, /api/workspace Édition optimiste 409, FTS5, habitudes >= 3, partage ACL 7 types.
Diffs & Uploads POST /api/sessions/{id}/uploads, /fork, diffs structurés Téléversement multipart borné + SHA-256, lignage complet sur fork.

3. Édition d’interface en direct (ui.patch), Surfaces v2 & Widgets

Hermes peut proposer des améliorations déclaratives et réversibles de votre espace de travail en temps réel (SSE ui.patch ou livraison Activité). Aucune exécution de code arbitraire et aucune WebView : chaque opération passe par un parseur déclaratif strict.

  • Bannière non bloquante (LiveUiPatchBar) : propose Voir · Appliquer · Annuler, historique complet des révisions et retour arrière atomique synchronisé avec la passerelle.
  • Blocs Surfaces v2 : grilles KPI (MetricGridBlock), sparklines et barres de progression dessinées sur Canvas (SparklineView), tableaux triables (DataTableBlock), interrupteurs/curseurs/filtres persistés par profil dans le stockage chiffré InstrumentStateStore.
  • Thèmes vérifiés WCAG-AA (ThemePalette) : les couleurs d’accent, surface ou texte dont le contraste est inférieur à 4.5:1 sont rejetées. Les surcharges mono-couleur en mode system survivent aux bascules Jour ↔ Nuit.
  • Widgets d’écran d’accueil isolés : HermesWidgetStore exige home_screen_safe: true, lie chaque widget à son ownerProfileId, refuse tout écrasement/suppression inter-profils, et purge automatiquement les widgets lors de l’oubli d’un profil.

4. Cerveau (Brain Studio) & Partage universel même-serveur

L’onglet Cerveau rassemble la mémoire de votre agent, vos notes, vos habitudes, vos compétences et vos fichiers d’espace de travail dans une interface calme sans jargon technique.

  • Mémoire & SOUL.md : gestion CRUD des souvenirs avec détection de conflit 409, annulation après suppression et édition du comportement par défaut du profil.
  • Notes intelligentes & Habitudes : prise de notes épinglables, et suggestions d’habitudes proposées uniquement après 3 répétitions observées (jamais d’automatisation silencieuse).
  • Partage universel (7 types) : partagez notes, compétences, surfaces, widgets, discussions, fichiers et briefings avec d’autres profils du même serveur (droits lecture / édition et révocation instantanée).
  • Recherche globale FTS5, Studio de compétences & Fichiers : recherche plein texte paginée, création de compétences alignée sur le budget 60 caractères du serveur, arbre de fichiers + diffs Git protégés contre la traversée de chemins, et bifurcation (fork) de fils avec lignage complet.

5. Intelligence ambiante sans root & Garde de confidentialité

Tout accès ambiant est désactivé par défaut (fail-closed) et s’active par profil depuis l’écran dédié. Aucun privilège root ni service d’accessibilité invasif n’est requis.

  • Pont de notifications (HermesNotificationListener) : ne lit que les applications explicitement autorisées, et est immédiatement suspendu lorsque le profil est verrouillé.
  • Garde anti-fuite (NotificationPrivacyGuard) : bloque systématiquement les codes OTP numériques ou alphanumériques, mots de passe temporaires, jetons API (sk-, ghp_, eyJ, blocs PEM) et notifications bancaires/authentificateurs.
  • Réponse rapide révisée : un brouillon de réponse proposé par Hermes ouvre toujours un dialogue de confirmation vérifiant l’état déverrouillé du profil et la liste d’autorisation au moment exact du clic.
  • Média, Calendrier, Contacts & État appareil : lecture strictement opt-in (CalendarContextReader, ContactsContextReader, DeviceContextSnapshot, MediaContextBridge).

6. Push zéro-fuite & Livraisons application fermée

Hermes Mobile prend en charge UnifiedPush (sans Google) et Firebase Cloud Messaging (FCM) avec une règle invariante : le message push ne transporte jamais de texte privé, de titre de discussion ni de contenu de livraison.

  • Réveil opaque : le pont server/mobile_push surveille en lecture seule runs_idempotency.db, cron/executions.db et mobile_state.db (mobile_deliveries) sans jamais lire title ni payload_json.
  • Déverrouillage avant récupération : toucher une notification ouvre le profil propriétaire, puis l’application récupère le contenu authentifié directement depuis votre passerelle.
  • Heures calmes & Urgence : les niveaux silent, normal et urgent respectent la politique locale PushPolicy et la file différée SQLite (v7).

7. Sécurité & Isolation des profils

  • Chiffrement local par profil : les clés API, brouillons, historiques de mise en page et états d’outils sont scellés dans des coffres chiffrés AES-GCM distincts par profil. Les sauvegardes cloud Android (allowBackup=false) et le trafic en clair (usesCleartextTraffic=false) sont désactivés.
  • Biométrie sûre & délai anti-force brute : BiometricVault n’accepte que BIOMETRIC_STRONG ou DEVICE_CREDENTIAL (jamais Class-2 weak), UnlockBackoff applique un délai exponentiel monotone persistant après échecs de phrase secrète, HermesApi.revoke() coupe tout flux SSE actif au verrouillage, et AccountStore.forget() efface atomiquement coffres, caches mémoire, widgets et pièces jointes.
  • Diagnostic de connexion & performance : Activité → Santé de la connexion exécute 6 sondes parallèles non bloquantes avec rapport technique expurgé ; le moteur de rendu coalesce les rafales SSE (64 ms), évite toute allocation dans onDraw() et libère ses caches bornés sous pression mémoire ou verrouillage.
  • Zéro WebView & EXIF supprimé : le rendu Markdown, code et tableaux est 100 % natif. Les photos importées ou capturées (via PrivateCaptureProvider non exporté) sont décodées puis ré-encodées sans métadonnées EXIF/GPS.
  • Validation en deux gestes : aucune action Android externe (agenda, alarme, SMS, courriel, navigation, partage, presse-papiers sensible) ne s’exécute sans aperçu complet et clic explicite dans DeviceReview.

8. Système de design (« Un espace de papier pour la conversation »)

L’interface Android et ce site partagent une source unique de vérité définie dans .impeccable/design.json et DESIGN.md : une colonne de lecture calme sur papier chaud, une couleur d’action vert sarcelle réservée aux actions réelles, des filets 1px et des cibles tactiles minimales de 48dp.

Warm paper#F7F5EF
Card paper#FFFEFA
Deep teal#225C50
Pale mint#DCEDE3
Green-black ink#172521
Dark paper#141D19
Dark card#1C2823
Night mint#A0D7BC
  • Règle du brouillon éditable : la dictée, les formulaires générés et les puces rapides préparent toujours un brouillon modifiable ; l’envoi exige toujours un geste séparé.
  • Règle des mesures honnêtes : chaque métrique (jetons, cache, latence) affiche son libellé clair au-dessus de sa valeur et ne remplace jamais une donnée indisponible par 0.

9. Vérification rapide & CI

Le dépôt fournit un lanceur hôte unifié (scripts/fast_check.py) exécutant en parallèle la vérification de la documentation, les tests du serveur push/nearby, les tests de déploiement et l’hygiène du code en ~12–20 secondes.

# 1. Parallel host checks (docs, server, deploy, verification scripts)
python3 scripts/fast_check.py

# 2. Android build, Lint, JVM unit tests & androidTest APK
./gradlew :app:assembleDebug :app:lintDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest --no-daemon

# 3. Verify generated documentation matches docs/sources/
python3 scripts/docs.py --check

Consultez la galerie de vérification API 36 pour voir les captures réelles sur téléphone et tablette issues des parcours automatisés.
